# Domain docs

## Layout and reading rules

This repo uses a single-context layout:

- GLOSSARY.md at the repo root defines domain terms.
- docs/adr/ contains architecture decision records.

Before exploring the codebase, read GLOSSARY.md and any ADRs relevant
to the area being explored.

If these files do not exist, proceed silently. Domain modeling creates
them when terms or decisions are resolved.

## Vocabulary

Use the glossary's terms in issues, proposals, hypotheses, and tests.
Reconsider unfamiliar terms or note a real vocabulary gap for domain modeling.

## Decisions

Explicitly identify any proposal that contradicts an existing ADR,
and explain why that decision should be reconsidered.
